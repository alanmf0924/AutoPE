# Spec Delta

## Purpose

让开源独立部署中的账号初始化、权限管理、评测、标注、审批和人工发布交接都能追溯到经验证的本地人员，同时明确区分旧本地演练记录，避免历史证据被误认成真实身份凭据。

## ADDED Requirements

### Requirement: 关键操作记录已核验本地操作者与结果
系统 SHALL 对受保护写操作、账号/角色管理及关键授权拒绝记录请求 ID、时间、动作、对象、结果与身份来源；成功操作记录服务端确认的稳定账号 ID 和当时生效角色。不得把浏览器自填字段当作审计主体。

#### Scenario: 已授权标注或审批
- **WHEN** 已登录人员完成标注、测试集批准、候选绑定、发布决定或 Dify 人工交接回填
- **THEN** 对应审计记录可关联该人员的稳定账号 ID、当时角色、`local_verified` 来源、对象版本与操作结果

#### Scenario: 初始化、改权与恢复
- **WHEN** 部署者初始化或恢复管理员，或管理员创建/停用账号、修改角色、发放重置凭据
- **THEN** 系统记录相应来源、发起者或受控恢复方式、目标账号及结果，不记录密码、重置凭据或会话 Secret

#### Scenario: 越权或自审被拒绝
- **WHEN** 已登录人员因缺少权限或与对象存在自审冲突而被拒绝
- **THEN** 系统记录拒绝类别与请求 ID，且不写入成功操作审计或改变业务对象

#### Scenario: 无法确认主体
- **WHEN** 未登录或会话无效的请求触发认证拒绝
- **THEN** 安全事件不虚构人员主体，也不记录密码或会话凭据

### Requirement: 旧本地身份记录保持原貌且可辨识
系统 SHALL 保留历史 `local-operator` 或由 `X-AutoPE-Actor` 形成的记录，并在审计查询中明确标记为“本地未核验身份”；不得将其倒填或合并到后续已核验本地账号。

#### Scenario: 查询历史本地记录
- **WHEN** 审计人员查看鉴权上线前的本地演练记录
- **THEN** 可看到原操作者文本及 `local_unverified` 来源提示，不能将该记录用作真实人员批准证明

#### Scenario: 新旧记录混合查询
- **WHEN** 同一对象同时存在历史本地记录和上线后的真实身份记录
- **THEN** 系统按身份来源区分两者，且原有标注、报告和发布证据内容不被改写

### Requirement: 审计查询遵循最小披露
系统 SHALL 仅向有审计或相应业务查看权限的人员返回必要审计字段；审计记录与错误响应不得包含密码、会话/重置凭据、Dify/模型 Secret、完整敏感正文或未授权对象内容。

#### Scenario: 审计员只读查看
- **WHEN** `auditor` 查询其授权范围内的操作历史
- **THEN** 系统返回已遮蔽的必要证据，但不允许审计员修改记录或触发外部模型/Dify 请求

#### Scenario: 无权查询或敏感字段
- **WHEN** 无相应查看权限的人员请求审计历史，或审计详情包含凭据及敏感正文
- **THEN** 系统拒绝查询或遮蔽敏感字段，不泄漏凭据或正文
