# Proposal

## Change Classification

平台鉴权同时改变安装初始化、浏览器会话、FastAPI 身份校验、逐接口权限、人工审批和审计证据，属于跨模块的高风险认证边界变更，符合本仓库的 OpenSpec 范围。

## Why

开源第一版必须在不接企业系统、不另建 OA 的情况下完成安装、创建管理员并登录使用。当前本地全角色旁路和客户端提供角色的做法不能可靠证明操作人身份，也不能支撑共享测试或生产环境的审批与审计。

## What Changes

- 第一版内置本地账号与一次性管理员初始化，管理员可创建、停用和重置平台账号；默认无公开注册、无预置账号或密码，不依赖邮件、OA 或企业身份源。
- 提供同源登录、登出、服务端会话、密码管理与失效处理；受保护 API 只信任服务端核验的账号和会话，部署环境失败关闭。
- 平台管理员负责账号和业务角色分配；服务端按五类业务角色及对象范围授权。审批提交必须携带当前证据摘要；历史对象由已核验人员对当前版本重新签署或重新提交，再交由不同人员审批。管理员身份不能跳过独立审批、高风险/红线门禁或 Dify 人工交接边界。
- 前端处理 401/403、会话过期和草稿恢复；关键提交重读当前证据和权限。审计区分新本地已核验账号与旧本地未核验记录，不追认历史身份。
- **BREAKING**：共享测试和生产环境的匿名业务请求、客户端自填角色/操作者、旧自签 HS256 角色令牌及本地全角色旁路不再可用于业务 API。

## Boundaries and Human Gates

- 非目标：新建独立 OA、员工/部门/流程管理、第一版企业 OIDC/SSO、复用现有 OA Cookie、邮件服务依赖、让 Worker 或 Dify Key 代表人工身份、自动发布/回滚生产 Dify 工作流。后续可另提可选企业身份接入，不是第一版安装门槛。
- 本变更涉及账号、会话和现有审计/审批数据的增量迁移；不得改写历史操作者、标注、报告或发布证据。迁移前备份并验证恢复路径，不能用重新打开全角色旁路作为生产回滚。
- 密码哈希、会话密钥和重置凭据属于 Secret；不得写进仓库、浏览器持久存储或日志。生产 Secret 仍按项目既有外部 Secret 解析要求管理，可由自托管的主机挂载提供，不要求企业 SaaS。
- 本提案不授权真实 Dify/模型调用、评测数据外传、生产流量切换、发布或回滚；这些仍按现有人工审批边界执行。
- 待确认项：初始管理员交付对象、正式域名/TLS、备份责任人、账号恢复责任人、五类角色与兼职冲突矩阵。仓库静态证据不等于生产安装验收。

## Capabilities

### New Capabilities

- `platform-identity`: 无企业系统依赖的本地账号初始化、登录会话、撤权与恢复。
- `platform-authorization`: 平台账号管理及五类业务角色、对象范围、独立审批和发布交接授权。
- `operator-audit`: 已核验本地账号操作审计与历史未核验记录的清晰区分。

### Modified Capabilities

无；当前 `openspec/specs/` 尚无已建立的能力规格。

## Impact

主要影响 `backend/app/security.py`、`backend/app/config.py`、`backend/app/main.py`、账号/会话/审计模型与 Alembic 迁移、`web/src/App.vue`、路由和 `web/src/services/api.ts`，以及同源入口、TLS、PostgreSQL、Worker 和 Secret 配置。新增初始化与账号管理操作；`/api/session` 响应契约及业务 API 的 401/403 行为会改变。`/api/health`、`/api/readyz` 仅保留最小探针信息。Dify 运行时 Key、模型 Key 和 Worker 身份仍归服务端管理。

## Acceptance Evidence

- 已执行的提案依据：仓库代码与 `docs/AUTHENTICATION_PLAN.md` 的静态核对；尚未实施或验证本地账号登录。
- 实施后需有隔离 PostgreSQL 上的首次初始化/重复初始化与恢复测试、密码和会话拒绝路径、后端权限/自审矩阵、浏览器登录与草稿恢复，以及自托管共享测试安装后的真实账号登录、停用和审计读回证据。Mock、SQLite 或本机端口可用不等于生产验收。
- 人工待办：确认初始管理员与恢复责任、角色和独立审批规则、正式域名/TLS、Secret/备份、共享测试与生产上线。证据齐备前不得标记生产鉴权完成。
