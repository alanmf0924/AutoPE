# AutoPE 平台鉴权实施与验收

状态：按 OpenSpec `add-platform-authentication` 实施中；本地登录基础链路不等于生产鉴权完成。

## 第一版边界

AutoPE 是可独立安装的开源评测控制面，第一版内置本地账号，不要求 OA、企业 IdP、OIDC/JWKS 或邮件服务器。首次由具备服务器权限的部署者签发短期一次性令牌，在同源设置页创建初始管理员；没有默认账号、默认密码或公开注册。企业 SSO 可在后续独立变更中选配，不复用 OA Cookie。

开发/自动测试可以显式使用本机全角色旁路，但其操作记录不能作为已核验人员证据。共享测试/生产要求 PostgreSQL、真实账号鉴权、独立 Worker、TLS 同源入口和主机挂载的外部 Secret 解析；当前部署档位的就绪探针仍固定为 503，直至浏览器、共享测试和上线门禁均验收并单独批准放行。

## 已落地的身份基础链路

- `backend/app/config.py` 区分 `development`、`test`、`shared_test`、`production`。部署档位拒绝 SQLite、全角色旁路、过短的 `AUTOPE_SESSION_SECRET`、缺失 Secret 挂载、非 HTTPS 来源、演示数据播种或未启用 Worker 心跳。
- `20261015_18` 增量创建本地账号、业务角色授予、会话和一次性凭据表；`20261015_19` 创建持久化登录限速表；`20261015_20` 增加复核对象与已核验标注员的分配关系；`20261015_21` 增加当前版本已核验贡献记录；`20261015_22` 增加审计身份来源、结果、当时角色和对象版本，不回填旧身份。密码用 Argon2id 哈希；会话和一次性令牌在数据库中只保存摘要。
- `python -m app.local_identity bootstrap-token` 仅在交互式服务器终端和空账号库中签发 15 分钟令牌；`GET /api/setup/status` 与 `POST /api/setup` 完成一次性初始化，来源不符、无效/过期/重用令牌或已初始化都会拒绝。
- `POST /api/login` 使用本地账号密码并对账号及来源限速；错误账号与错误密码统一返回 401，超限返回 429。成功后只向浏览器发送 `HttpOnly`、`SameSite=Lax` 的不透明 Cookie；共享测试/生产还设置 `Secure`。会话令牌不放 URL 或 Web Storage。
- `GET /api/session` 从服务端当前账号与角色读取主体，同时给浏览器内存中的 CSRF 证明。受保护写请求需同源 `Origin` 与 `X-CSRF-Token`；登出、会话过期、账号停用和存储不可用分别拒绝。会话空闲上限 30 分钟、绝对上限 8 小时；`POST /api/logout` 撤销会话。
- 旧自签 HS256 角色令牌不再被受保护 API 接受。Worker、Dify Key 和模型 Key 仍是服务凭据，不能代表人员身份。

### 当前 API 契约

| 路径 | 请求与结果 | 身份边界 |
| --- | --- | --- |
| `GET /api/setup/status` | 返回 `initialized: boolean` | 匿名可读；不返回账号明细 |
| `POST /api/setup` | 初始化令牌、登录名、展示名和密码；成功返回账号 ID | 仅空账号库、有效一次性令牌且 `Origin` 匹配 |
| `POST /api/login` | 登录名和密码；成功设置 `autope_session` Cookie | 错误凭据统一 401，限速 429；同源 `Origin` |
| `GET /api/session` | 返回账号 ID、展示名、当前角色、管理员标志、`allowed_actions`、`session_state` 及 CSRF 证明 | 必须有服务端有效会话；不返回密码或 Cookie 值 |
| `POST /api/logout` | 撤销当前会话并清除 Cookie | 有效会话、同源 `Origin` 与 `X-CSRF-Token` |
| `POST /api/password/change` | 本人提交旧密码和新密码；成功撤销旧会话 | 有效会话、同源与 CSRF |
| `POST /api/password/reset` | 一次性凭据和新密码；成功撤销旧会话 | 同源 `Origin`、15 分钟凭据；无需当前会话 |
| `GET/POST /api/accounts` | 查看账号 / 创建无密码账号并返回一次性邀请凭据 | 平台管理员，不自动赋予审批角色 |
| `PATCH /api/accounts/{id}` | 修改展示名、状态、平台管理权或业务角色 | 平台管理员，停用立即撤销旧会话 |
| `POST /api/accounts/{id}/reset-token` | 返回一次性重置凭据 | 平台管理员，凭据只显示一次 |

所有受保护写请求都须提交会话对应的 `X-CSRF-Token`，同时通过同源 `Origin` 检查。401 表示需要重新登录，403 表示拒绝当前动作，503 表示身份存储不可用；前端不得自动重放失败写请求。`AUTOPE_SESSION_SECRET` 轮换会使旧 Cookie 失效，部署前须在服务器安全保存并分发同一密钥给 API 实例。

`allowed_actions` 是当前账号的粗粒度页面动作提示，始终从服务端现时角色重算；它不替代每个 API 的对象级授权。平台管理权只增加 `accounts.manage`，不隐式增加 `approvals.manage`。当前业务角色、标注分配、证据摘要和独立审批规则见 [业务授权矩阵](AUTHORIZATION_MATRIX.md)。页面可见性和本地测试都不构成生产授权验收。

## 尚未完成，不能据此上线

- 当前服务端角色/标注分配矩阵已有本地隔离测试；旧记录 `local_unverified` 与新账号 `local_verified` 的审计读回已用合成旧行、隔离 PostgreSQL 和本地 API 测试验证，尚缺共享环境验收。账号管理和恢复已有基础 API/页面；隔离浏览器已创建五类虚构账号、赋权和撤权。2026-10-15 在新的临时 SQLite 库中，由人工在首次设置页完成管理员创建、登录，并在一次性邀请设密页完成第二个标注账号的设密和登录；服务端读回 `initialized=true`、初始化凭据与该账号邀请凭据均已消费，审计有 `identity.bootstrap_completed` 和 `identity.password_recovered`。代理未读取或记录人工输入的密码。此证据只证明本机浏览器流程，不代替共享测试 PostgreSQL/TLS 验收。
- 已实现当前证据版本贡献主体和独立审批的后端隔离测试；前端从测试集/报告详情读取 `evidence_digest`，在批准、交接创建和人工回填写请求中发送 `If-Match`。前端类型检查、构建和 lint 已通过，但这些新写入链路的浏览器端到端提交与共享测试真实双账号验收尚未完成，不能视为上线批准。
- 五类账号入口、双账号登录、直接 URL 越权、管理员浏览器建人/改权、标注与审批的 401 页面内草稿恢复、证据变化后的 412 拒绝及撤权后的 403 已在独立临时 SQLite 库与浏览器验证；拒绝后未产生发布决策。只读审计员不显示标注表单，纯标注员保存虚构标注后可看到“分配给你的待判断已全部处理”，无需调用其无权访问的报告接口。另一隔离浏览器实例中，虚构待回填交接的未提交版本 ID 和说明在会话失效、同账号重新登录后仍保留，旧报告摘要被标为需重新核对；刷新页面后草稿字段清空，数据库交接仍为 `awaiting_dify`，没有回填版本 ID。未勾选“已在 Dify 发布”，未访问 Dify。2026-10-15 的第二账号登录后，左侧只显示“逐条审核”；直接打开 `/accounts` 显示“无权访问此页面”，直接请求 `/api/accounts` 返回管理员权限拒绝，审计新增 `security.admin_denied`。经用户确认后，用随机合成账号在本机无界面 Chromium 复核登录前后 `localStorage`/`sessionStorage` 均无键，密码和会话令牌不在 URL 或持久存储，`autope_session` Cookie 为 `HttpOnly`、`SameSite=Lax` 且脚本不可读；本机 HTTP 的 `Secure=false` 仅适用于测试档位。另在数据库副本中移开会话表，浏览器重载后隐藏业务导航、显示“操作已锁定”和“身份服务暂不可用”，再次点击重试仍锁定；随后关闭并清理故障副本，原临时库未变。共享测试真实双账号安装及 HTTPS `Secure=true` 验收仍待完成。临时 SQLite/浏览器/构建不构成生产验收。
- 生产域名/TLS、初始管理员交付、Secret、备份/回退、角色矩阵和正式流量由部署与业务负责人批准。真实 Dify/模型调用和生产发布不在本鉴权任务中自动执行。

## 操作与恢复约定

未登录或会话失效返回 401，页面要求重新登录；已登录但无权限、CSRF 或同源证明失败返回 403，不自动重试；身份存储不可用返回 503，业务写入失败关闭，不能记为评测质量失败。标注、整份报告审批与人工回填的未提交表单仅在当前页面内存保留：同一账号重新登录后重新读取当前权限和对象证据，保留填写但阻止沿用旧摘要；重新核对后再次确认，绝不自动重放失败写请求。主动退出、改密或换账号会清除原页面实例；刷新页面也不会持久保存草稿。标注证据变化时须明确采用新证据或放弃草稿；审批/交接证据变化时须查看报告并手动读取当前摘要，服务端仍拒绝过期版本。标注、审批和未提交回填草稿均已做隔离浏览器恢复测试；真实 Dify 发布后的回填不属于本机鉴权验收。平台只记录生产 Dify 的人工控制台交接，不自动发布或回滚。

详细任务、验收和人工边界见 [OpenSpec 任务清单](../openspec/changes/add-platform-authentication/tasks.md) 与 [自托管部署说明](SELF_HOSTED_DEPLOYMENT.md)。
