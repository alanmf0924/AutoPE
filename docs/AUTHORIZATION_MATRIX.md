“读全部”仅指此独立 AutoPE 安装实例里的业务对象；不隐含跨实例权限。平台管理员权限只管理账号，不自动获得表中任何业务权限；多角色账号按角色并集获得操作，但对象分配和自审冲突不能被并集绕过。

复核分配由已核验 `operator` 调用 `PATCH /api/review-cases/{id}/assignments`，提交 `{"account_ids": ["account-..."]}` 覆盖当前分配；`operator` 和 `auditor` 可用同路径的 `GET` 读取当前分配。写入只接受当前有效且具有 `annotator` 角色的本地账号。未分配的标注员列表不含该对象，直接请求详情、标注或重开均返回 403，响应不包含请求/回答正文。旧复核记录默认**无分配**，不会按历史 `reviewer_id` 自动认领。撤销分配不会删除既有标注与审计。开发/测试显式开启 `AUTOPE_AUTH_DISABLED=true` 时，本机演示身份无真实账号，复核分配校验仅在该模式旁路；该模式在共享测试与生产被配置校验拒绝。

候选生成与评测的角色许可不等于授权外部传输；仍需对应端点原有的显式外传确认。所有发布交接仍只记录人工 Dify 控制台动作，不自动调用生产发布。当前贡献人、独立审批与审计来源已在后端隔离实现，前端已接上 `If-Match` 提交，但浏览器端到端写入及共享测试验收尚未完成；本矩阵**不是上线批准**。

已核验部署下，测试集批准、发布决定、人工交接创建和确认还必须带 `If-Match: "<当前证据摘要>"`。测试集详情和评测报告详情在响应正文的 `evidence_digest` 与 `ETag` 中提供该摘要；缺失返回 428、过期返回 412。即使摘要匹配，服务端仍会重新计算当前版本、可信贡献主体及风险硬门禁；自审返回 403，历史证据缺可信重签返回 409。`operator` 使用 `POST /api/datasets/{id}/attest` 在当前摘要上重签旧测试集；旧候选绑定由 `prompt_owner` 重新提交绑定证明，旧标注由获分配的 `annotator` 重新提交。重签不会改写旧记录，且重签人也不能批准该对象。缺少可信工作流版本快照的旧评测仍需在获授权的隔离环境重跑，不能靠重签伪造版本证据。

审计查询目前仅开放给 `auditor`，最多一次返回 200 条按时间倒序的固定字段：`id`、`actor_id`、`identity_source`、`actor_roles`、`action`、`outcome`、`resource_type`、`resource_id`、`object_version`、`request_id`、`created_at`。不返回 `detail`，避免旧自由格式记录中含敏感正文。新写入的 `detail` 仅接受固定的技术元数据键；拒绝审计不复制请求体或凭据。`local_verified` 表示经本地会话确认的账号及当时角色，`local_unverified` 表示旧演练/显式本地旁路身份，`anonymous` 表示无法确认主体的认证拒绝，`server_operator`/`one_time_credential` 分别表示受控服务器恢复/一次性恢复凭据，`service` 表示后台任务。旧 `actor_id` 不改写、不自动认领为新账号；旧行的结果列默认 `succeeded` 仅表示原审计动作曾写入，不等于旧身份已核验。对象版本列仅记录当次能确定的版本或摘要，历史行为空；空值不得当作版本已核验。
