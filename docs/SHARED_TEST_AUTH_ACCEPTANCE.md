## 4.1 安装与真实身份链路

1. 在专用环境核对 `AUTOPE_ENVIRONMENT=shared_test`、`AUTOPE_AUTH_DISABLED=false`、`AUTOPE_SEED_DEMO_DATA=false`、PostgreSQL 连接、单个同源 HTTPS `AUTOPE_ALLOWED_ORIGINS`、长度至少 32 字符的外部注入 `AUTOPE_SESSION_SECRET`、`AUTOPE_SECRET_RESOLVER=external`、只读绝对路径 `AUTOPE_EXTERNAL_SECRET_DIR`、`AUTOPE_REQUIRE_WORKER_HEARTBEAT=true`。只记录配置项是否满足，不回显值。前端与 API 同源，入口不得公开数据库、Worker 或 Secret。
2. 记录迁移前备份与恢复点；在目标库执行 Alembic 升级，读回版本、身份/审计表及旧证据计数。先启动独立评测 Worker 和候选 Worker，确认各自心跳，再启动 API 与 TLS 入口。当前共享测试 `/api/readyz` 固定 503 是未放行门禁，不能伪报就绪或据此切正式流量；共享测试访问需在受控入口单独安排。
3. 由服务器负责人在交互式终端签发一次性初始化令牌；由指定人员在 HTTPS 设置页创建管理员并登录。验证重复初始化、伪造令牌和过期令牌被拒绝；令牌正文不留存。管理员创建第二名测试人员账号，后者本人设密并登录；两人分别完成登出和重新登录。
4. 记录浏览器与 HTTP 证据：Cookie 的 `HttpOnly`、`Secure`、`SameSite` 属性；同源带 CSRF 写入成功、缺失/错误 CSRF 拒绝；匿名请求 401、非管理员直接调用账号 API 403、五类角色允许入口与受限 URL/API、停用后旧会话失效、改权后旧会话不保留权限。证据只保存状态码、请求 ID、必要的角色/对象标识和脱敏字段，不保存 Cookie/CSRF/密码。
5. 用获批测试数据验证操作者准备当前测试集版本、不同主体审批、同人自审拒绝和旧摘要 `If-Match` 拒绝；读回批准状态与 `local_verified` 审计，确认旧 `local_unverified` 行原样保留。无需为鉴权验收触发真实评测、候选生成或 Dify 发布。

每个检查点均记录：时间、环境版本、执行人、预期与实际 HTTP 状态、浏览器可见结果、数据库/审计只读读回、证据位置、是否通过及异常处理。仅监听端口、截图、SQLite 或 Mock 不构成此项通过。

## 4.2 故障、回退与恢复演练

在批准的维护窗口、可恢复的专用测试库中逐项执行并记录前后数据摘要；先证明备份可恢复到**独立目标库**，未经单独批准不覆盖运行中数据库。

| 演练 | 预期结果 | 停止条件 |
| --- | --- | --- |
| 会话存储不可用 | 已登录写请求失败关闭；页面锁定并可重试；不生成业务成功审计，也不记作评测质量失败 | 出现绕过鉴权或写入成功 |
| 重复初始化 | 已有账号时拒绝第二管理员和旧/伪造令牌 | 账号数或角色意外变化 |
| 服务回退 | 使用预先批准的兼容版本或只读维护；保留新身份表、账号、审计与业务证据，不重新开放全角色旁路 | 旧版本无法安全读取新状态，转只读并修复向前 |
| PostgreSQL 备份恢复 | 在独立库恢复后比较迁移版本、账号/角色、历史 `actor_id`、审计与业务对象计数/摘要 | 缺失或改写历史证据 |
| Worker 故障 | 心跳/任务状态与报告质量结论分离；不把运行错误判为模型质量失败 | 错误被误判为 GO 或质量失败 |

记录每次故障注入和恢复的开始/结束、执行人与批准人、影响范围、备份标识、客观读回、残余风险。不得删除原库、清空卷、覆盖既有账号或修改 Dify 发布状态来完成演练。

## 4.3 上线门禁汇总

将后端自动测试、Alembic/旧数据读回、本地浏览器和共享测试 HTTP/浏览器/数据库证据链接到 [鉴权上线门禁记录](AUTHENTICATION_RELEASE_GATE.md)。逐项确认高风险/红线失败不能被总分覆盖、待人工复核或运行错误不能给 GO、不同主体审批与证据版本可追溯、生产 Dify 发布/回滚仍由人员在控制台执行。缺任一批准、证据或恢复能力时保持“待批准”；生产流量切换与移除 `/api/readyz` 固定 503 需另行批准和实施。
