## 人工与自动化责任分界

| 阶段 | 人工必须决定/操作 | 平台自动执行与留痕 |
| --- | --- | --- |
| 目标登记 | 提供 Dify 应用、已发布 Workflow UUID、密钥引用并确认隔离边界 | 加密保存本地凭据、校验目标与版本约束 |
| 黄金集 | 业务确认输入、风险、预期契约和可执行断言；冻结后由审批角色批准 | 上传校验、版本冻结、哈希与自动判定覆盖预检 |
| 基线 | 选择批准的冻结集与目标，授权有费用的真实调用 | Worker 排队、逐条 Dify 调用、进度/耗时、证据、错误与报告 |
| 候选生成 | 明确批准黄金集契约发送到指定模型/地址 | DSPy 生成并保存 Prompt、哈希、来源任务与审计；不会改 Dify |
| 隔离绑定 | 将 Prompt 应用到独立 Dify 测试应用并发布测试版本；核对发布 UUID 与 Prompt 哈希后具名确认 | 校验独立应用与版本绑定，拒绝未经证明的候选对比 |
| 候选对比 | 选择全量或同版本失败/待判定定向复测；对不可自动判定、失败或错误逐条复核 | 复用合规基线证据，逐条调用候选，生成差异和风险门禁；自动通过不进人工队列 |
| 业务标注 | 四维评分、依据、编辑重标；高风险/红线须人工判断，不能覆盖安全硬失败 | 按运行分组，待标注/已标注分离，保留修订历史，实时重算报告 |
| 发布/回滚 | 审批人决定 GO/NO-GO；GO 后在 Dify 控制台人工发布或恢复旧版重新发布，回填新 UUID | 仅在完整 GO 时允许发布交接，证据变化使旧决定失效；记录人工回填，不冒充 Dify 自动核验 |
