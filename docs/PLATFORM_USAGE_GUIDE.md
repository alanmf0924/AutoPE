# Dify AutoPE 平台使用说明

Dify AutoPE 是独立的评测控制面：它调用 Dify 作为被测目标，平台负责保存证据、评分、人工审核和发布门禁。

## 安装后首次登录与账号管理

第一版无需 OA、企业 IdP 或邮件服务。空账号库时，部署者在服务器交互式终端执行 `cd backend && uv run python -m app.local_identity bootstrap-token`，把仅显示一次、15 分钟有效的令牌带到平台首次设置页，创建管理员；系统没有默认账号、默认密码或开放注册。设置完成后用新账号登录。

管理员进入「账号管理」，填写登录名、显示名称和必要的业务角色创建账号。页面仅显示一次邀请凭据；通过安全渠道交给本人，本人在登录页选择「使用一次性凭据重置密码」设置密码。无需邮箱。管理员也可给现有账号发放一次性重置凭据、停用账号或调整角色；停用和改密后旧会话失效。平台管理权只管理账号，不自动赋予审批权限。

导航按当前会话角色收起不可查看的工作台；直接打开受限 URL 会看到“无权访问此页面”，服务端 API 仍独立执行 403 授权。401 要重新登录；身份服务不可用时页面锁定操作并提供重试。已登录者可在右上角修改自身密码或退出。密码、一次性令牌与会话 Cookie 不放在 URL 或浏览器持久存储。审计员只读；页面里隐藏不属于当前角色的主要写入表单，但真正权限始终由后端判断。

若编辑标注、报告审批或发布版本回填期间会话过期，同一账号重新登录后，本页会暂存尚未提交的填写，并重新读取当前权限及证据；请核对新版本后再次确认，系统不会自动重试先前写入。刷新页面、主动退出或更换账号不会保留草稿。证据摘要变化时，旧批准和交接不能直接沿用；请先阅读当前测试集或报告，再点击页面的“读取当前版本”。

## 一次基线评测

1. 在「Dify 目标」登记被测应用。只填写必要信息：名称、运行类型（Chatflow 或 Workflow）、本机服务地址、运行时路径和 Dify App API Key。Key 只在保存时填写，保存后不会回显。
2. 在「测试集」上传 JSON 用例并确认内容，先冻结版本，再由有审批权限的人员单独批准。未批准的冻结集不能用于评测；冻结后不能修改内容。
3. 在「评测运行」选择「基线回归」、测试集和 Baseline 目标，创建评测。Worker 会逐条调用 Dify 并保存请求、响应、耗时和错误证据。
4. 在「评测报告」查看 GO / NO-GO / 待人工复核、风险判定覆盖、四维评分和延迟。未判定的用例不展示为 0% 或 0 分，成本未采集时显示“未采集”。普通用例通过率必须不低于 85%，高风险与红线用例必须为 100%。
5. 在本次「评测报告」可为最多 10 条待判断用例一次性生成 AI 辅助建议。确认框会说明送往已配置 DeepSeek 地址的字段与可能费用；生成进度显示在报告页。AI 的四项分数和依据只是草稿，不改变报告。进入「逐条审核」后，对照原/新回答、预期规则和实际工具记录，可点「核对无误，采用 AI 建议」、修改分数或理由后点「按我的修改保存」，也可清空建议自行填写。只有保存的人工作为正式结论，之后仍可重新标注；原始 AI 建议和每次人工版本均保留。

## 运行进度、中断与删除

- 「评测运行」每 3 秒刷新一次，显示已完成用例数 / 总用例数、百分比、排队等待或已运行时间。基线回归逐条调用 Dify，因此总耗时主要取决于用例数量和每条 Dify 响应时间。
- 新建评测可选择「全部用例」或「仅未通过 / 待判定」。后者须选同一冻结集、同一目标及候选版本、同一基线引用的已完成运行，且相关 Dify 目标必须锁定已发布工作流 UUID。平台复制自动通过与人工已确认通过的结果及其来源 ID；人工已通过的标注证据也复制到新运行，仍可重新标注。只对失败、调用错误或待判定用例重新调用；报告仍覆盖全量用例。不同候选版本必须全量评测，不能拼接旧版通过证据。自动通过不产生人工标注；没有可执行评分规则时，结果仍待人工复核，不能被当作自动通过。
- 对排队中或运行中的任务，可点击「中断」。平台会立即标记中断；若已有一条 Dify 请求在执行，会在该请求结束后停止，不再开始下一条。
- 只有已中断或执行失败、且尚未被业务人工标注的任务可以删除。已完成或已标注任务保留为审计证据，不能从页面删除。

## 使用自动评分

每条需要自动门禁的用例都要包含四项 `evaluation_rules`。缺少规则时，平台仍会保留 Dify 的真实响应，但不会编造自动分数，而是送人工审核。

## 候选 Prompt 对比

1. 在「Prompt 优化」查看已配置的 DSPy 模型与外部地址。只有明确同意把所选黄金集的用户输入、风险等级和预期契约发送到该地址后，才能创建候选生成任务。该任务在独立 Worker 中运行；页面显示排队、模型生成、完成或失败及耗时。模型生成阶段进度无法量化，不显示虚假百分比。也可以在平台外生成后手工登记。
2. 克隆一个独立 Dify 应用，将候选 Prompt 应用到**克隆应用**并在克隆应用发布测试版本；Dify 运行时 API 不能直接运行未发布草稿。不要因此修改基线应用。登记两个目标时，建议从各自 Dify 版本历史复制实际已发布 Workflow UUID，填入目标的「Dify 已发布工作流版本 ID」以锁定评测版本；仅填写版本标识不会锁定执行版本。
3. 在「Prompt 优化」登记候选并绑定隔离候选应用。候选与基线的应用 ID 和版本指纹必须不同。点击候选列表或生成任务中的详情入口，可查看完整 Prompt、SHA-256、生成来源和关联评测。
4. 先在「评测运行」完成同一冻结集与基线目标的基线回归。再选择「DSPy 候选对比」并指定要复用的已完成基线运行；平台核对集内容哈希、目标版本、结果数量与执行错误后，直接复用其逐条基线回答，本轮只调用候选 10 条，不重复产生基线模型费用。报告会展示 Baseline 与 Candidate 的差异和风险门禁。API 未指定 `baseline_run_id` 时仍会实时重跑基线，调用次数需单独预算。

## 发布原则

平台不会自动改写 Dify 生产 Prompt，也不会自动发布。只有完成候选对比、报告 GO、全部用例已判定且无真实失败或调用错误时，审批人才能记录“批准进入人工发布流程”；也可记录驳回及依据。审批决定绑定当时的报告与标注证据，重新标注后旧决定自动显示为失效。

批准后可创建“发布候选”交接，先查看隔离候选应用中的内容，**检查并保留基线应用已有未发布草稿改动**，再由有权限人员把获批内容应用到基线应用草稿并在基线应用发布。从基线应用版本历史复制**新发布版本 UUID**回填操作说明。回滚时在基线应用版本历史选择旧版、创建回滚交接、恢复旧版到草稿，**然后重新发布**并回填新版本 UUID；仅恢复草稿不算完成回滚。平台保存操作人与审计记录，但目前无法用运行时 API Key 核验 Dify 控制台发布结果，回填状态明确标记为“人工回填 · 未经 Dify API 核验”。灰度、流量观察仍需在 Dify/部署侧完成。
