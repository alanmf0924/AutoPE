# 单机自托管部署边界（共享测试待批准）

本页描述第一版目标拓扑，不代表当前版本已可安全上线。`add-platform-authentication` 已完成本地实现与隔离浏览器验收，尚缺获批准的共享测试、故障演练和上线门禁；共享测试和生产档位会拒绝旧 Bearer 鉴权。请勿把现有本机演示模式暴露给其他用户。具体执行与取证要求见 [共享测试执行与取证单](SHARED_TEST_AUTH_ACCEPTANCE.md)。

## 一台服务器，多个独立服务

同一台服务器可以部署 TLS/同源入口、静态前端、FastAPI、评测 Worker、候选 Worker、AI 辅助标注 Worker 和 PostgreSQL。API 与 Worker 使用同一数据库和部署环境；API 不直接执行异步评测工作。入口只公开同源 Web/API，数据库、Worker 和挂载的 Secret 不公开。单机不是高可用，需另定备份、监控和恢复责任人。

第一版账号由平台自身管理，不要求安装 OA、企业 IdP 或邮件服务器。首次安装须由有服务器/容器管理权限的部署者完成一次性管理员初始化；设置、登录、邀请、恢复和对象授权已有本地隔离测试，但共享环境验收尚未完成，不得使用开发旁路替代。

## 环境档位

| 档位 | 用途 | 鉴权旁路 | 数据库与 Secret | 入口 |
| --- | --- | --- | --- | --- |
| `development` / `test` | 明确隔离的本机开发与自动测试 | 过渡期允许，禁止对外暴露 | 可使用隔离 SQLite/本地设置 | 仅 loopback HTTP |
| `shared_test` | 多人共享测试 | 禁止 | PostgreSQL、挂载的外部 Secret 目录 | TLS 同源入口 |
| `production` | 正式服务 | 禁止 | PostgreSQL、挂载的外部 Secret 目录 | TLS 同源入口 |

共享测试和生产配置必须提供 `AUTOPE_DATABASE_URL`、`AUTOPE_ALLOWED_ORIGINS`（单个同源 HTTPS 地址）、`AUTOPE_AUTH_DISABLED=false`、`AUTOPE_SESSION_SECRET`（至少 32 字符）、`AUTOPE_SECRET_RESOLVER=external`、存在的绝对路径 `AUTOPE_EXTERNAL_SECRET_DIR`，以及 `AUTOPE_REQUIRE_WORKER_HEARTBEAT=true`。禁止演示数据自动播种。挂载 Secret 可以来自自托管主机的受控只读目录，不以企业 SaaS 为前提；不能把真实值写进 `.env.example`、仓库或日志。共享测试与生产均使用挂载文件解析 Dify Secret，拒绝通过页面内联写入 Dify Key，也不回退到本地环境变量或数据库凭据库。

共享测试与生产 API 启动时先核对账号迁移表、外部 Secret 解析器，以及评测 Worker 与候选 Worker 各自近期的独立心跳；缺一则拒绝启动。部署者须将两个 Worker 作为独立进程/服务先启动，心跳只能证明近期活动，不能代替进程监控或任务质量验收。目标状态下 `/api/readyz` 会在心跳过期时返回非就绪；当前共享测试/生产档位还固定返回 503，防止完整授权与审计门禁完成前接入流量。建议依次启动 PostgreSQL、执行 Alembic 迁移、启动各 Worker、再启动 API 与同源入口，并以 HTTP 就绪和真实登录/权限测试验收，而非只看端口。迁移、生产凭据接入、备份恢复和正式流量切换均需部署负责人批准。

鉴权任务完成前，即使上述配置校验通过，也不会接受旧 HS256 Bearer 令牌，不能据此宣称共享测试或生产身份链路已就绪。对象级授权、审批、审计与浏览器流程已有本地证据；真实安装、故障/恢复和上线门禁仍须在获批准的共享测试环境完成。

## 身份存储迁移与回退

`20261015_18` 增量创建 `local_accounts`、`local_role_grants`、`local_sessions` 和 `local_one_time_credentials`；`20261015_19` 新增 `local_login_attempts`；`20261015_20` 新增 `review_case_assignments`；`20261015_21` 新增 `evidence_contributions`；`20261015_22` 为既有 `audit_events` 增加身份来源、结果、角色快照和对象版本列，不改写原 `actor_id`、标注或报告。部署前由负责人对目标 PostgreSQL 做备份并核对恢复点，再执行 `cd backend && uv run alembic upgrade head`。升级后核对 `alembic_version`、七张新表，以及旧审计原文和 `local_unverified` 标记的读回。该迁移已在无持久卷的隔离 PostgreSQL 上用合成旧行验证，不代表共享测试或生产迁移完成。

开发中已在无持久卷的临时 PostgreSQL 16 容器验证 `20261015_18` 升降级、同名账号并发唯一约束和备份恢复，验证 `20261015_19` 的升级、回退与重新升级，以及迁移到 `20261015_21` 后新分配表与贡献表存在；这不是用户现有数据库或生产数据的恢复证明。生产回退优先保持新表与已有账号/证据，回退兼容应用或进入只读维护；迁移降级会删除新身份或贡献数据，**不得**作为已有账号的生产回退手段。任何真实备份恢复需部署负责人单独批准。

## 首次管理员初始化

完成迁移后，由有服务器/容器管理权限的部署者在连接目标数据库的交互式终端运行 `cd backend && uv run python -m app.local_identity bootstrap-token`。命令只在空账号库中签发 15 分钟有效的一次性令牌；再次运行会使旧令牌失效。令牌仅显示在当前终端，不应复制进 `.env`、日志或工单。

部署者通过同源 HTTPS 页面填写令牌、登录名、显示名称及至少 12 位密码。平台将密码保存为 Argon2id 哈希，令牌只存摘要；成功后创建唯一初始管理员及 `operator` 业务角色，设置入口随即关闭。页面本身不会自动登录，而是进入登录页。账号管理、密码恢复、授权与审计已有本地实现和隔离验收，但未完成共享测试，因此不可据此对外开放平台。

## 邀请、改密与管理员恢复

已登录平台管理员可在“账号管理”创建账号并选择业务角色；账号初始不设密码，平台只显示一次 15 分钟邀请凭据，由管理员经安全渠道交付本人。本人在登录页使用它设置密码后登录，不依赖 SMTP。管理员可重新签发一次性重置凭据，后签发的凭据使此前未用凭据失效；账号停用会立即撤销旧会话。平台管理权与 `approver` 业务角色分离，当前已禁止停用或降级自己的平台管理权。

已登录人员可在页面修改自己的密码，成功后所有旧会话撤销，需重新登录。管理员自身无法登录时，**只有拥有目标服务器/容器和数据库连接权限的恢复责任人**在交互式终端执行 `cd backend && uv run python -m app.local_recovery recover-admin LOGIN_NAME`，并将 15 分钟一次性凭据交给管理员在登录页重置密码。CLI 仅为仍处于启用状态的平台管理员签发；无 TTY、目标不存在或普通账号均拒绝。签发与消费写入身份审计事件，但不记录令牌正文。服务器权限持有人及凭据交付渠道须由部署方事先确认；不得把令牌写入日志、工单、URL 或环境文件。
