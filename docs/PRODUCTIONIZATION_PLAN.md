# Dify AutoPE 生产化执行计划

## 目标与边界

本平台独立于 Dify：平台负责数据集、评测证据、硬门禁、人工标注和发布审批；
Dify 只作为被测运行时。自动评分和候选 Prompt 生成均不得直接修改生产 Dify 配置。

## 阶段 0：运行边界与配置

- 使用显式环境配置区分 development、test、production。
- 生产环境必须配置 PostgreSQL、受信任前端来源、密钥解析器和应用签名密钥；缺失时拒绝启动。
- API Key 仅保存引用名，解析和使用只发生在服务端，响应中不返回密钥或其值。
- 增加 `/api/readyz`，把依赖可用性与存活检查区分开。

**验收：** 未配置生产依赖时 `/api/readyz` 非就绪；开发和测试使用明确的隔离配置。

## 阶段 1：持久化、身份和审计

- 引入 SQLAlchemy 数据模型与 Alembic 迁移，替换进程内存存储。
- 为用户、角色、数据集、用例、标注、目标、候选、评测运行、发布决定与审计事件建立不可变快照关系。
- 为所有写操作记录操作者、请求 ID、时间、前后状态和原因。
- 建立最小 RBAC：标注员、评测运营、Prompt 负责人、发布审批人、审计只读。

**验收：** 重启后数据仍在；越权请求返回 403；所有关键状态迁移均有审计记录。

## 阶段 2：真实 Dify 异步评测

- 构建服务端 Dify Runtime Adapter，统一 workflow/chatflow 请求和响应。
- 评测运行状态机：queued → running → completed/failed/cancelled；仅允许受控迁移。
- 使用 Worker 队列处理并发、超时、重试、退避、幂等键和取消；保存每用例请求摘要、响应、错误与耗时。
- 不在浏览器暴露 Dify URL 中的敏感信息、Authorization Header 或密钥引用。

**验收：** 受控 Dify 沙箱能够完成真实运行；超时可重试而不重复执行；重启后任务可恢复。

## 阶段 3：测试集与人工标注闭环

- CSV/XLSX 上传、字段映射、逐行校验、脱敏扫描、重复检测与错误下载。
- 数据集版本冻结后不可修改；新修改必须派生新版本。
- 标注任务按角色分配，支持四维评分、证据、双人复核、争议处理与抽检。
- 服务端基于普通 ≥85%、高风险 100%、红线 100% 计算门禁；安全/越权/泄露硬失败不能被总分抵消。

**验收：** 一个业务同学可独立完成上传—标注—复核—冻结；每项评分均可追溯到用例和证据。

## 阶段 4：报告、审批、灰度与运行保障

- 报告支持任务实时进度、用例级钻取、筛选、导出和可访问的图表文本替代。
- 发布仅对已冻结的报告开放，审批人具名确认；高风险/红线失败时服务端不可绕过。
- 引入 shadow/canary/rollback 状态与操作审计；平台只提交发布提案，不直接改生产 Prompt。
- 提供结构化日志、指标、追踪、告警、备份恢复、负载和故障演练脚本。

**验收：** 灰度与回滚均可审计；压测与故障演练无丢任务、无重复执行、无越权数据泄露。

## 非目标

- 不把业务生产 Dify API Key 写入仓库、浏览器、测试夹具或评测报告。
- 不因自动评分通过而自动上线 Prompt。
- 不将本地 SQLite、Mock Dify 或截图作为生产集成证据。
